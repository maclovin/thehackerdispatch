# Security

## Untrusted content

Feeds and articles may contain prompt injection, and no human reviews them before publishing. Mitigations:

- the model has no tools;
- output is restricted to a JSON schema and validated on the server;
- URLs never come from model output: published links always come from the feed;
- fields have length limits;
- the fixed contract tells the model that news content is data, not instructions.

## SSRF

Ingest, publish, and "test feed" fetch arbitrary URLs. The shared `fetch` client:

- resolves DNS and blocks private, loopback, and link-local ranges plus the cloud metadata endpoint, including after every redirect;
- accepts only `http`/`https`;
- follows at most 5 redirects;
- enforces size and time limits.

## XSS

Comments and model-generated text go through Markdown → HTML sanitized with an allowlist. Strict CSP.

## CSRF and sessions

`http.CrossOriginProtection` on every state-changing request, `HttpOnly`/`Secure`/`SameSite=Lax` cookies, and sessions that users and admins can revoke. See [Authentication](authentication.md#sessions).

## Passwords

- Generated by a CSPRNG, never chosen by a human, stored only as argon2id hashes.
- Plaintext exists only in memory and in the one-time display (admin screen, user screen, or the master password file).
- A wait after consecutive failures, and a cap on concurrent password checks.

## Secrets

- LLM API keys are entered in the panel, stored encrypted (AES-256-GCM with `SECRETS_KEY`), and never shown again.
- The Slack token and the OIDC client secret live in environment variables or a secret manager.

## Audit

Every admin action and every login attempt goes to `audit_log` (kept 90 days).

## Data retention

Expired content is deleted from the database, but it still exists in backups until they rotate. Keep backup retention short and well known.
